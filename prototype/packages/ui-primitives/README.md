# @reinforce/ui-primitives + UI kit conventions (П1–П10)

shadcn `new-york-v4` on Tailwind v4 / React 19, split so same component ships styles-only into Astro, full React into apps. Folder-per-slice, subpath-only exports — **no root barrel**.

## Packages

- **`@reinforce/ui-primitives`** — framework-agnostic styling. Exports (1) `cva` recipes where semantic axis remain (`buttonVariants` — `default | destructive | secondary | ghost | ghost-destructive | link`: two filled CTAs, one flat second tier, chrome-less ghosts, a text link; `badgeVariants`, `alertVariants`, `tabsListVariants`, `toggleVariants`, `navigationMenuTriggerStyle`, `navLinkVariants` (`desktop | mobile` — quiet nav text-link, not button), `sheetContentVariants`, `scrollAreaScrollbarVariants`, `tokenChipVariants` (`pill | flat` + logo/fallback twins; **token grammar law: number → logo → ticker — chip is a SUFFIX after the numeral, never a leading badge**), plus size/interactive-only recipes for card/input/textarea/select-trigger/checkbox/radio-group-item/switch/progress/tabs-trigger, `tileIconVariants` (`tone` × `size` medallion under a lucide glyph — status tones ride `--tile-*` from ui-tokens and flip per theme, chrome tones ride `--card`/`--border`; a `bg-<tone>/10` fill here is the bug the tokens exist to prevent), `inlineNoteVariants` (`tone: warning | neutral` — no blue tone: a note does not press; flat inset note INSIDE a glass card, deliberately not a second glass layer like `alert`; text roles `inlineNoteTitleClass`/`inlineNoteBodyClass` or single-line `inlineNoteTextVariants`; React twin `ui-react/inline-note` with optional icon/title/role), plus `headingVariants`/`textVariants`); (2) plain `xxxClass` constants per slot (accordion item, dialog/popover/tooltip content, command root/item, table container/row, skeleton, inline-code, `navbar` shell/brand/mobile-sheet slots, `insetPanelClass` — recessed quiet zone inside a glass card, layout/padding stay at consumer, `setting-row` slots — icon + label + description + trailing control, surface owned by parent card, …). **Every visual class string live here, not in `ui-react`.** **Glass — default; opt-in `variant: 'glass*'` dropped.** Subpath per component. (`collapsible` ships `collapsibleContentClass` — height morph via `animate-collapsible-down/up` on `--radix-collapsible-content-height`; padding goes on an INNER wrapper, never on Content — border-box padding breaks the height:0 keyframe end state.) Astro use: `<a class={buttonVariants({ variant: 'secondary' })}>` zero-JS.

- **`@reinforce/ui-react`** — full shadcn kit on umbrella `radix-ui` (`import { Slot, Dialog, ... } from "radix-ui"`). Tailwind v4 patterns: no `forwardRef`, `data-slot` on every primitive, `data-variant`/`data-size` for variant styling, `Slot.Root` for `asChild`. `cn` from `@reinforce/ui-styles/cn`. **Every component import class strings from `ui-primitives`** — React layer = radix behavior + `data-*` + `cn(primitiveClass, className)`. Subpath per component, no barrel, no `default` export. Cross-slice import via subpath alias (`@reinforce/ui-react/dialog`), never relative `../X/index.tsx` (TS5097 / `allowImportingTsExtensions` off).

### Primitives-only exceptions (no `ui-react` twin)

- **`nav-link` + `navbar`** — consumers = Astro landing + blog shells (`apps/{landing,blog}/src/layouts/{Header,LanguageSwitcher,SocialMenu}.astro`). `navbarMenu*` is the shared `<details>` popover shell (base/scroll/align/direction) — language switcher and social menu both hang off it, so it carries no per-menu name. React layer add when dapp need it (YAGNI).
- **`external-link`** — `externalLinkIconClass`, canonical external-link marker: lucide `arrow-up-right` (NOT `external-link`), `size-3.5 text-muted-foreground`, on `group`-hover → `text-primary` + diagonal nudge (motion-safe). Consumer put `group` on the anchor, icon inline after label. `externalLinkVariants({ linked })` carries the row itself: `linked: true` = link affordance (primary + focus-ring + `group`), `false` = same inline-flex row rendered as plain text — a proof label whose url is `null` (unmapped chain) keeps its shape instead of branching markup. Consumers: every inline external link in dapp + landing (`_shared/ExternalLink.astro`) — proof rows, explorer/contract links, stepper proofs, receipt records, pool tags. Button CTAs that leave the app carry the same `arrow-up-right` glyph, trailing the label; the cva row is for anchors only.
- **`not-found-scene`** — brand 404 scene «4 ⟨BrandMark⟩ 4»: class recipes (`notFoundFigureVariants` `hero | compact` sets fluid font-size, digit/mark/canvas slots em-scale off it) + `mountNotFoundScene(root)` — the ONE runtime-behavior export in this package (vanilla DOM, zero deps; why here: identical scene consumed by Astro landing/blog inline `<script>` and dapp `useEffect`, React twin = wrapper with no value). Canvas particles assemble `brandMarkPath`, palette sampled from `--palette-blue-*`/`--palette-amber-400` CSS vars (theme-reactive via MutationObserver on `html.class`); pointer → plane tilt + particle repulsion, single rAF loop, sleeps when settled, pauses on `document.hidden`. Reduced-motion → static frame, no listeners-driven motion. No-JS → `[data-nfs-fallback]` SVG stays visible (mount hides it). Digit depth = `.nfs-digit` text-shadow stack in ui-styles effects (em-based, scales with figure size). Package tsconfig carries DOM lib for this slice.
- **`charts`** — chart visual language shared by Astro landing + dapp SVG tiles; runtime deps `d3-shape`/`d3-array`/`ts-pattern` (catalog) — `ts-pattern` rides into the Astro island bundle through `bucketize.ts`/`engine.ts`/`geometry.ts`. Geometry: `donutPaths` = `pie().sort(null)` (input order = legend order; d3 default sorts descending) + `arc()` (100%-share full annulus works, no circle special-case) with a parallel 2.4-unit gap between segments (`padRadius` = outer) — the bars' 2px `gap-0.5` at the 200px render, so segments never need a stroke; paths centered at origin — consumer wraps segments in `<g transform={donutCenterTransform}>`; `DONUT` config = size 240 / center 120 / outer 110 / inner 72. `linePath`/`areaPath` index-positioned with `.defined()` null gaps (honest holes, no interpolation); `sparkPath` self-scaling via `valueExtent`, `sparkAreaPath` the same line closed down to the frame floor for a gradient fill under it; `linearScale` hand-rolled (no d3-scale); `chartTicks` (nice + ticks), `nearestIndex` (bisectCenter, crosshair lookup). **A series whose story is its fine structure takes `fittedTicks({lo,hi,count,minSpan})`, not a domain anchored to a reference** — the API publishes the backing ratio in whole bps, so a `Math.min(lo, 100)` axis rendered a 0.01 pp day-step at 0.83 px and the climb read as a flat line. It pads the extent by 10 % and widens a span below `minSpan` around its midpoint, so a dead-flat series gets a band instead of a degenerate domain. The reference line then rides `withinDomain(domain, value)`: **out of view = drawn nowhere, legend entry included** — a dashed rule clamped to the axis floor would claim 100 % sits where it does not, and the tick labels (`100.97 %…101.01 %`) already state the side. Consumers: landing `ProofPage/RatioHistory.astro` + dapp `transparency/domain/ratio-history-plot-vm.ts`, which must stay twins. A rate read against zero (both APY charts) keeps its `Math.min(lo, 0)` anchor — a truncated yield axis magnifies noise, and the anchor is also what keeps a flat series non-degenerate there. SVG defs ids ONLY via `donutIds(idPrefix)` — per-instance prefix, fixed `proof-seg-<i>` collision on multi-donut pages (tested). Palette: `chartSeriesVars` ordered `var(--chart-1..5)` + `chartLiabilityVars` (`soft` = `--warning-soft`, `strong` = `--destructive`); components never hardcode chart colors; `seriesColor(i)` cycles. Class recipes: `chartFrameClass`, `chartLegendPillClass` (flat inset pill), `chartAxisLabelClass` (SVG `fill-muted-foreground`), `chartBarTrackClass` + `chartBarFillClass` (one-share bar — track holds the neutral groove, fill takes `width` + `background` inline from the consumer, so a brand-coloured share bar needs no new class string), and the whole tooltip family — `chartTooltipClass` (floating tier, tooltip-parity) + `chartTooltipTitleClass` / `chartTooltipGroupClass` (`first:` arm = no top border) / `chartTooltipRowVariants({ tone: 'series' | 'context' })` / `chartTooltipLabelClass` / `chartTooltipSwatchClass` / `chartTooltipNoteClass`: the dapp tooltip component and the landing island's HTML string builder print the same rows, so the strings live here and neither re-derives them (a landing group must sit inside one wrapper element for `first:` to mean the first group). **Window engine + calendar bucketize live here too** (`engine.ts`, `bucketize.ts`) — legit kit because pure math over numbers and ISO strings: zero DOM, zero Intl, zero locale, zero framework, so Astro `<script>` island and React tile run identical arithmetic. `engine.ts` = window over point INDICES: `clampWindow`/`panWindow`/`projectWindow` (fractional `windowStart` = sub-pixel pan, `phase` handed back for the transform), `windowForRange`/`rangeEnabled`/`autoGranularity`, cap `MAX_VISIBLE_POINTS` 400. `bucketize.ts` = daily ISO series → ISO-week (`W`, Monday-stamped) or calendar-month (`M`) buckets, `last`/`mean` aggregate, empty bucket stays `null` (honest gap, no carry-forward). Calendar math is `Temporal.PlainDate` — `Date` banned — and touches bucket EDGES only: one `PlainDate` walk per bucket, each point placed by `bisectRight` over the ISO-string starts. `bucketize` reruns every pan frame, so a per-point `PlainDate.from` is a perf regression, not a cleanup. **Consumer bundle must have the global `Temporal` installed**: `@reinforce/temporal-shim` is a devDependency here (tests need the global; runtime consumers install it at their own entry-point) — and an Astro `<script>` island is its own entry-point, so it must carry `import '@reinforce/temporal-shim/install';` as first line or `bucketize` throws `Temporal is not defined` in the browser. `geometry.ts` = plot math both surfaces share: `plotStep`/`plotScale` (`point` = mark ON the tick, `band` = mark centred in its slot), `clampPlotX`, `axisLabelAnchor`, `axisLabelIndices` (3 labels under 480 px, else 5), `isTap` (8 px travel budget); `tooltip-placement.ts` = `placeTooltip(frame,size,position,avoidY) → {left,top}` (flip at the right edge, drop to the bottom when the tooltip would shade the highlighted point) — the DOM write stays at the consumer, landing sets `left`/`top`, dapp sets a `translate3d` transform so its own `w-fit` box is never measured through its computed position. Border: geometry + calendar stay in kit, **formatting and locale stay at the consumer** — axis/tick/tooltip strings and `Intl.*` (landing `src/charts/format.ts`), pointer/drag wiring (landing `src/charts/pan.ts`, dapp `src/shared/ui/chart/*`). Consumers: landing `sections/YieldPage/{ApyCards,ApyChart,Contribution}.astro` + `sections/ProofPage/{Donuts,RatioHistory,Strategies}.astro` + `sections/_shared/ShareBar.astro` + `src/charts/{format,spark,tooltip}.ts`, dapp `contexts/{analytics,transparency}/{domain,ui}/*` + `shared/ui/chart/*` (React shell over these folds — pan/crosshair/tooltip hooks; it stays app-local until a second React consumer justifies a `ui-react` twin).
- **`comparison-table`** — consumer = `apps/landing/src/sections/Compare/Compare.astro` only. Slots: `comparisonTableContainerClass`/`comparisonTableScrollContainerClass`/`comparisonTableHighlightOverlayClass`/`comparisonTableStickyLabelClass` + `comparisonTableCellVariants` (`role: label | head | body`)/`comparisonTableDotVariants` (`state: filled | filled-highlight | empty` × `size: sm | md`)/`comparisonTableValueVariants` (`size: sm | md` × `highlight: boolean`). Architecture — flat CSS Grid: consumer set column-template, each cell get explicit `grid-column`/`grid-row` (overlay in highlight column with `grid-row: 1 / span totalRows`, else break auto-placement). Highlight = single grid-item overlay (`comparisonTableHighlightOverlayClass` — neutral `bg-foreground/[0.05]` + 3:1 `ring-border-control`, overlay carry `grid-column` + `grid-row: 1 / -1`), not `border-x` per cell — remove "segmented staircase" on dark theme. Neutral, not blue (K3): the column is a selection, not a button; highlighted dots and values go full foreground, the rest 80%. Mobile scroll wrapper carry `mask-image` right fade-edge; sticky-label get shadow. Row-hover — consumer wrap each row in `<div class="contents group/row">`: wrapper transparent for grid layout, give hover zone, `group-hover/row:*` from `comparisonTableCellVariants` highlight every cell in row.

## Adding components

Use shadcn CLI against `packages/ui-react/components.json` (aliases `utils → @reinforce/ui-styles/cn`):

```bash
mise exec -- pnpm dlx shadcn@latest add <name> --cwd packages/ui-react
```

CLI drop files under `src/components/ui/<name>.tsx`. **Move into folder-per-slice form** (`src/<name>/index.tsx`), add `package.json#exports` entry, then **extract every class string into `packages/ui-primitives/src/<name>/index.ts`** (`cva` as `xxxVariants`, inline strings as `xxxClass`). Replace inline strings in `ui-react` with imports. **No pre-emptive re-implement shadcn components.**

`useSortedClasses` (Biome nursery) is an **error** across app and kit class sources.

## Typography (Heading / Text / InlineCode)

Standardized scale live as cva-recipes in `@reinforce/ui-primitives/typography`, React sugar in `@reinforce/ui-react/typography` — same recipe both ways, **identical visual output between dapp and landing**.

- Astro: `<h1 class={headingVariants({ size: 'display' })}>`, `<p class={textVariants({ variant: 'lead' })}>`, `<code class={inlineCodeClass}>`.
- dapp: `<Heading as="h1" size="display">`, `<Text variant="lead">`, `<InlineCode>`. `Heading.as` owns document semantics; `Heading.size` owns visual scale. Both required; no defaults or `asChild` escape.

`headingVariants.size`: `display | h1 | h1-compact | h2` (border-bottom for documentary docs) `| h3 | h4 | h5 | h6 | page | section` — `page` 24/30 w650 (page name, head of the main object), `section` 17/24 w600 (card heading). Body `text-sm` = 14/21 (`--text-sm--line-height` in ui-styles), plus `text-meta` 13/18 and `text-row` 15/22; caption `text-xs` 12/16. Figures carry no tracking except the hero (−0.035em). `textVariants.variant`: `lead | subtitle | body | small | muted | mono | numeric | numeric-card | numeric-amount | numeric-display | numeric-hero | numeric-hero-unit`. `Heading` has no default; `Text.variant` defaults to `body`. `h1-compact` — h1 one step smaller (`text-3xl`/`lg:text-4xl`), `subtitle` — `lead` one step smaller (`text-base`/`md:text-lg`); both non-semantic size-tokens, like `display`.

**No `.ty-*` utilities or custom `--text-*` tokens** — Tailwind v4 built-in `text-xs..text-9xl` foundation. **Exception**: `display` (heading) + `numeric-{amount,display,hero,hero-unit}` (text) — only roles with fluid `[font-size:clamp(...)]`. `numeric-hero`/`numeric-hero-unit` scale by **container** (`cqi`) for `@container` hero stats (transparency proof big ratio + unit); the rest scale by viewport (`vw`). Any other arbitrary `font-size` (incl. clamp) forbidden — extend kit, not call-site. All `numeric*` roles draw in `font-figure` (Sans, dotted zero `ss04`, tabular); `mono` is for verifiable strings only — addresses, hashes, formulas, UTC stamps. One main figure per screen, capped at 60px: `numeric-hero` = `clamp(2rem, 8.5cqi, 3.75rem)`, weight 600, `-0.02em` (`numeric-display` the same voice by `vw`); its unit rides `numeric-hero-unit` — muted, `clamp(0.8rem, 3.4cqi, 1.5rem)`.

**Figure (K5)** — `figure`: `splitFigure(text, locale)` cuts a formatted figure at the locale's decimal separator into `{ whole, fraction, tail }` (no separator → all `whole`); `figureFractionClass` keeps cents full size at foreground 42%, `figureUnitClass` a trailing unit at 0.4em muted Sans. Dimmed cents only on a scene's main figure — ledger, sums, forms, the proof strip and running text print plain cents. Money prints 2 decimals, truncated; under a cent reads «< $0.01»; compact notation only from $10,000, three significant digits («$2.90M»). Wrappers: dapp `shared/ui/figure.tsx`, landing `sections/_shared/Figure.astro`.

**Text scale (K4).** Interface sizes 11 · 12 · 13 · 14 · 15 · 16 · 18 · 20 · 24 · 30 px, nothing below 11. Reading text 17 (article, docs, whitepaper), H3 20, H2 24, stretch 100%. Help answers are interface, not reading: 15 in the dapp (`accordionContentClass`), 16 on the site. A reading column takes `max-w-(--measure-reading)` (`ui-tokens`, 32em ≈ 68 characters at any size) — never `max-w-[68ch]`, which measures in `0` glyphs and runs ~76 characters of Plex. Table heads (`tableHeadClass`) are 12px muted, normal case. One `overline` per card (section label), never a caps label under each figure. Input text ≥ 16px on touch.

**Display roles = strong signal, use sparingly.** Reserved for brand moments: page hero, top-line balance on dashboard, success state after operation ("Bridged $12,408"). **No use** in header chips (`chip-glass-ghost` + `Text variant="numeric"`), table cells, list rows, portfolio cards — standard `numeric` (text-sm) and plain `h1..h6`. Bug-fix invariant: Plex Condensed load up to weight 700, so `display` use `font-bold` (not `font-extrabold` — else browser synthesize bold).

## Consumer rule — reuse, don't reinvent

Kit — **single source of truth** for visual layer in `apps/*`. For every React component in `apps/dapp/src/**` (and every `.astro` in `apps/landing`):

- **Kit slot exist → use it.** `<Card>` / `<Button>` / `<Tabs>` from `@reinforce/ui-react/<slot>`; Astro consume class strings / cva recipes from `@reinforce/ui-primitives/<slot>` direct. Inline construct `<div className="rounded-2xl bg-card/80 backdrop-blur ...">` for surface — drift; use `<Card>`.
- **Slot / variant missing → extend kit, not call-site.** New `cva` arm in `ui-primitives/<slot>`, mirror-prop in `ui-react/<slot>` → consume. dapp and Astro landing inherit one definition auto.
- **No re-derived class strings.** П1–П7 (radii / hover / focus / disabled / transitions / sizes / glass-tier) — kit-owned. Inline `motion-safe:hover:-translate-y-0.5 transition-all duration-200` outside kit slot = drift; either kit recipe already cover it, or recipe need new arm.
- **Semantic tokens over hardcode.** `bg-input-bg`, `text-muted-foreground`, `ring-ring` — never `dark:bg-zinc-800/30`, never raw hex. Missing semantics — extend `@reinforce/ui-tokens`, not local call site.
- **Colour roles (K3).** Blue (`primary`) = something to press: buttons, links, focus. Never a headline, a selected segment, a highlighted menu row or a figure. Green (`success`) = money that arrived (yield, a received deposit amount) or a finished success state; an APY, a deposit, a streak or points stay neutral. Amber/red = attention/failure only. A figure takes `text-foreground`; its sign carries direction.
- **Apply to Astro and React equal.** Single-source recipes yield identical visual output between dapp and landing (see typography section above).
- **Kit owns no copy.** Visible and screen-reader text enters package components as required, already translated props; never English constants or optional defaults.

When extending kit, extend golden reference too (`apps/dapp/src/routes/design-system.tsx`).

## Conventions (П1–П10)

Standardization contract, mandatory for every edit under `ui-{tokens,styles,primitives,react}`.

- **П1. Radii + shape** — `rounded-md`: inline controls (input/textarea/select-trigger/toggle, amount-field shell), table cell, dialog/sheet close, button `link`. List menus (dropdown/select content) sit on `rounded-(--radius-control)` with `p-1`, their items on `rounded-[calc(var(--radius-control)-0.25rem)]` — `inner = outer − padding`. Tabs list `rounded-md` + `p-1`, its trigger and the navbar menu row (`navbarMenuItemClass`) `rounded-[calc(var(--radius-control)-0.25rem)]` — same `inner = outer − padding` rule. `rounded-xl` (= `--radius-control` too): tooltip, **shell-islands** (sidebar and header via `glass-island`; flush to viewport, `rounded-2xl` look adrift). `rounded-2xl` (= `--radius-card`, 20px): **all** floating surfaces (dialog, sheet content, popover, hover-card, command root, nav-menu viewport) **and all glass containers** (card, alert, FAQ group, table container). `rounded-(--radius-stage)` (24px): the screen's one stage, via `stageClass` only. `rounded-md` = `--radius-control` (12px). The scale lives in `ui-tokens` (`--radius-control` 12 · `--radius-card` 20 · `--radius-stage` 24) and `ui-styles` maps `rounded-md`/`rounded-2xl` onto it, so a radius change is a token edit. Outer surfaces pair radius with `corner-squircle`; unsupported browsers keep the radius fallback. `rounded-full`: **all buttons except `link`**, badge, avatar, switch, progress, radio item, segment chip; never squircle. Checkbox `rounded-[0.3125rem]`. `rounded-xs`/`rounded-3xl` forbidden.
- **П2. Hover** — utilities in `effects/index.css` (`.glass-hover`, `.glass-soft-hover`, `.glass-link`, `.hover-glass-tint`, `.link-underline-slide`, `hover-neutral-soft` for nav and list rows). Buttons: lift applies only to the filled CTAs (`default | destructive`) — `transition-all duration-200 motion-safe:hover:-translate-y-0.5 motion-safe:active:translate-y-[0.5px]`; `secondary` is flat and only presses (`motion-press`). Colored halo live in `:hover` blocks of `.btn-cta-*` (stronger tinted box-shadow + inset highlight via `--surface-tint-strong`); a filled button never lightens — its fill (`--btn-fill`) only darkens from the tone, so the white label holds 4.5:1 at rest and on hover. Busy (`aria-busy`) controls stay full-strength: `disabled-state` fades only a disabled control that is not busy. **`ghost` / `ghost-destructive` no lift** — ghost by role "no chrome", motion in dense lists look jittery without halo to justify. `link` also no lift. Icon sizes (`icon-sm | icon-md | icon-lg`) override base lift to `scale-105` via compound variant — work for all variants incl. ghost. Inline `hover:bg-primary/90` kept only in solid-`badge` (shadcn idiom). Menu/select/command rows hover neutral (`bg-foreground/6`), sidebar rows too (hover 5%, current row 7% + 6% hairline ring + weight) — blue stays on the action, never on a highlighted or current row. **No new one-off hover strings.**
- **П3. Focus** — `focus-ring` (= `outline-none focus-visible:ring-[3px] focus-visible:ring-ring/50`), destructive — `focus-ring-destructive`. Items inside dropdown/select/command highlight neutral (`focus:bg-foreground/6`, `data-[highlighted]`) for Radix keyboard nav — same as hover.
- **П4. Disabled** — `disabled-state` (native controls, `disabled:` API) or `disabled-data-state` (Radix items, `data-[disabled]` API). `disabled:cursor-not-allowed` forbidden.
- **П5. Transitions** — `transition-colors` (text/bg/border on hover/focus), `transition-[color,box-shadow]` (controls with focus-ring), `transition-opacity` (fade), `transition-all` (only surface effects with translate). Duration `duration-200` (exception: state-driven slide in sheet/dialog/tooltip).
- **П6. Size scale** — `size: 'sm' | 'default' | 'lg'`. button/input/textarea/select-trigger/toggle: `h-8/h-9/h-10`. tabs trigger: `h-7 px-2 / h-8 px-2.5 / h-9 px-3`. checkbox/radio item: `sm` `size-4` · default `size-5` (20px). switch: `sm` `h-4 w-7` · default `h-6.5 w-11` (44×26). Controls carry a 3:1 border (`border-border-control`), not glass. badge: `h-5/h-6/h-7`. card: `gap-4 py-4 / gap-6 py-6 / gap-8 py-8` (+ headerVariants/contentVariants/footerVariants). progress: `h-1/h-2/h-3`. dialog: `max-w-sm p-4 / max-w-lg p-6 / max-w-2xl p-8`, extra `xl` = `max-w-4xl p-6` (wide media/composite dialog; width grows, padding stays default for content density + unchanged mobile). **Button (K8):** `sm` 34 (row action) · `compact` 40 (header, beside the 40px chips) · `md` 42 (default, dialogs) · `lg` 44 (a screen's main actions), plus two special sizes — `cta` (`h-auto min-h-13 w-full` — 52, form hero CTA; `CtaButton` in ui-react adds optional `sub` second line, rendered only when it carries real info), `xl` (`h-auto min-h-14`, `text-[0.9375rem]` — screen-primary action that must outweigh `lg`: funnel connect CTAs, lesson dialog); icons share the heights: `icon-sm | icon-md | icon-lg` (`size-8/size-9/size-10`). Glyph inside a button 17px by default; no letter-spacing; filled/ghost/link semibold, `secondary` medium. No `xs`: below 32 a target is too small. Every button and control carries `touch-target` — a ≥ 44px hit area on `pointer: coarse`, visual size unchanged. In-field actions (Max, Paste) are `fieldActionChipClass` pills: blue text because they press, a hairline ring, `touch-target`. One blue fill per screen's content (`default`); every other action is `secondary`/`ghost` — the header's «My wallets» does not count.
- **П7. Glass coverage — DEFAULT for surface/floating.** Tier mapping:
  - `glass-island` (`rounded-xl`, inset highlight + primary-tint halo) — **shell islands**: sticky sidebar and header islands.
  - `chip-glass-ghost` (glass pill — gradient + inset highlight + neutral drop-shadow + hover-lift) — **info chips in header** (USDRL balance, op status). Shell chrome like the sidebar; a content button never borrows it.
  - `stageClass` (`glass-strong stage-glow corner-squircle rounded-(--radius-stage)`) — **the screen's main block, one per screen** (Portfolio hero, Transparency/Yield hero, Rewards status, 404, onboarding card; Help has no stage). `stage-glow` = two static radials (primary top-start, violet 295 bottom-end, `--stage-glow-*`); a stage never animates on its own — motion answers an action. Inside: `stageHeadClass` (page name, `Heading size="page"`), `stageSentenceClass` (15/22 second ink), `stageFootClass` (hairline row of meta facts). Below the stage: `actionDockClass` (r28 card around a screen action + its 13px note), `sectionCardClass` (r20 list card, `section` heading + `sectionCardLinkClass`). Lists inside ride `list-row` (`listRowVariants`, 34px disc via `listRowDiscVariants`, 15/22 title, 13/18 meta, 15/22 figure + 13/18 unit). Above the stage only `pageStripClass` (r20 glass row: 18px glyph, 14/21 title, 12/16 meta, `sm` action) — the dapp's connectivity strip. Actions that cannot run right now dim whole with `actionsPausedClass` (+ `inert`) and say why in `actionsPausedNoteClass`.
  - `glass-strong` (`rounded-2xl`, tooltip — `rounded-xl`) — floating menus, popovers, tooltips. Dialogs and sheets ride `glass-overlay` (near-opaque `--overlay-surface`) over the one `--overlay` scrim (3px blur). A sheet opens on `sheetBarClass` (title 17/24 `sheetBarTitleClass`, 34px ghost icon actions `sheetBarActionClass`, close included) and lays its body on `sheetBodyClass` (p-3, gap 10). Cards inside a sheet are `insetCardClass` (r18, 3.5% fill, 8% ring, p-14) with `insetCardHeadClass` (38px `insetCardAvatarClass`, identity, 32px r10 `insetCardActionClass` icons, `insetCardDividerClass`) and `insetCardBodyClass` below a hairline. Resource rows ride `meter` (`Meter`/`MeterBar` in dapp `shared/ui/meter`: 7px marker, 13/18 label, figure + 12/16 unit, 4px bar, `meterNoteClass` 12/16 second ink; `meterStatusClass` for the card's status line). Holdings ride `asset-list` (20/26 total, r14 `assetGroupClass` for the primary asset, 32/1fr/auto rows, 13/18 per-network rows, `assetLinkClass` 12/16 link). Chain filters are `filterChipClass` (30px). Lists inside a sheet use `listRowVariants({ density: 'compact' })` (30px ring-only disc, 14/21 title, 12/16 meta, 13/18 figure) under `listRowGroupLabelClass` day labels in a `listRowSectionClass`, closed by a `listRowMoreClass` ghost link.
  - `glass` (`rounded-2xl`) — surface containers (card, alert, accordion item, table container): 8% rim, neutral shadow (`--glass-halo`). Inside a card, an inset is flat (`insetPanelClass`, inline note) — never glass on glass.
  - `glass-destructive` — failure tint on top of a glass tier (alert `destructive`): recolours the glass ground from `--card` + 24% `--destructive`, rim 30%, because a `bg-*` utility loses to `.glass` in the same layer. An info surface is not blue: it is the plain glass (K3).
  - `surface-inset` — **every inset inside a surface is flat**: muted 35% fill + 60% border, no blur. `insetPanelClass` (`surface-inset rounded-md`) for panels and step shells; tabs list, progress track, chart legend pills and onboarding steps ride the same utility. Controls (input, textarea, select trigger, checkbox, radio, switch, amount field) are flat `bg-input-bg` with a 3:1 `border-control` border. No glass on glass: `glass-weak` has no kit consumer left.
  - **Segments (D26)** — selected = foreground text on a raised plate (`bg-card shadow-sm`) with a 3:1 border; unselected = muted, no fill. `tabsTriggerVariants`, `toggleVariants`, `segmentChipClass` (`aria-pressed` driven, `segmentSelectedClass` for class-swapping islands) and dapp `segmented-chip` all speak it. Never a blue fill for a selected state.
  - `skeleton-block` — placeholder shapes (foreground-tinted flat base, no glass: on light theme `glass-weak` no contrast with tinted backdrop, visibility degrade to invisible). Motion = one breath (`filter: opacity` 1 ↔ 0.45, 1.2s alternate), never a travelling glint: a sweep that doesn't fully leave the box reads as a broken loop, and a moving spot is noise on glass. `filter`, not `opacity`, so it never fights the 150ms anti-flash `skeleton-appear`. One global clock via `--skeleton-sync` (2400ms = full cycle) + `--i` stagger.
  - `skeleton-lines` — same base + breath, as the *background* of a transparent inline element wrapping the real copy; `box-decoration-break: clone` → one bar per line fragment. Twin of a text block inherits its wrapping, line count and per-line width instead of restating widths (`ui-react/skeleton#SkeletonLines`). **Shape law:** every text bar is the same glyph-high pill (`--skeleton-bar: 0.7em`, semicircle caps) at every size, cut per fragment by a 3-layer mask (two caps + body); the box keeps the real line box, so layout is untouched. Painting the whole content area (~1.3em) turned big figures into fat capsules, and rounding a thinner stripe by the box's own radius bent its ends into a lens. Shapes that twin a real element (button, chip, icon, chart) keep that element's shape. `skeletonLinesVariants({ surface: 'primary' })` (`skeleton-on-primary`) re-inks the bar with `--primary-foreground` for copy on a primary fill, where the foreground tint vanishes.
  - Buttons — filled CTAs (`default | destructive`) share lift physics, a gradient that only darkens from the tone and a hover-halo (`.btn-cta` / `.btn-cta-destructive`); `secondary` (`.btn-cta-secondary`) is the one flat second tier: 5% foreground + 16% hairline in both themes, no shadow, no gloss, no blue, no lift; `ghost` / `ghost-destructive` — `.btn-ghost-soft` / `.btn-ghost-destructive` no lift (list-row / unobtrusive); `.btn-ghost-quiet` modifier keeps a ghost muted until hover (blog social/follow icon rows — chrome that must not read as a call to action); `link` text-only. Aria-invalid and destructive focus use `ring-ring-destructive` (NOT `ring-destructive/20 dark:ring-destructive/40` — these hardcodes dropped). Badges solid (chip legibility). Variant API for glass dropped. `sonner` (`.toast-glass`) — glass-island parity + accent-chip icon; variant via `--toast-accent` (success → success, warning → warning, error → destructive; info, default and loading stay neutral glass — an info toast does not press, so it is not blue); no `richColors` — accent itself carry semantics.
- **П8. Dark — semantic tokens over hardcode.** `--input-bg` / `--switch-track{,-checked}` / `--switch-thumb{,-checked}` declared in `ui-tokens/theme/index.css` (`:root` + `.dark`) and exposed via `@theme inline`. Use `bg-input-bg` — **no** hardcode `dark:bg-input/30`.
- **П9. Motion-safe** — all `transform` effects wrapped in `motion-safe:` or live in CSS utility with `@media (prefers-reduced-motion: reduce)` (pattern from `.glass-hover`). Button press — via `motion-press`.
- **П10. Floating rhythm** — `dialog` size variants with different padding (П6). list-style content (`dropdown-menu`, `select`, `command items`) — `p-1`. prose-style (`popover`, `hover-card`) — `p-4`. `tooltip` — `px-3 py-1.5`. `sheet content` — `p-6`.

## Accordion on native `<details>`

A FAQ group is ONE surface with dividers: wrap rows in `accordionGroupClass` (glass, `divide-y`) — inside a dialog `accordionInsetGroupClass` (flat inset). `accordionItemClass` is the row alone (height morph, no chrome); a lone disclosure (blog TOC) adds `accordionSurfaceClass`. Answers read at `font-stretch: 100%` (`accordionContentInnerClass`; any long text opts in with `data-longform`).

`accordion` rows carry **two interaction contracts**: Radix `data-[state=open]` (for `ui-react`) and native `<details>`/`<summary>` (for zero-JS Astro). Each selector is inert against the other markup, so the two current branches remain independent.

Astro markup:

```astro
<details class={accordionItemClass} name="faq">
  <summary class={accordionTriggerClass}>
    Вопрос
    <svg class={accordionTriggerIconClass}><!-- chevron --></svg>
  </summary>
  <div class={accordionContentInnerClass}>Ответ</div>
</details>
```

- `accordionItemClass` (on `<details>`) animate height via `::details-content` (pseudo-element belong to `<details>`, not child `div`). Require `interpolate-size: allow-keywords` on `:root` at consumer — without it `<details>` toggle instant (graceful degradation), content always work.
- `accordionTriggerClass` (on `<summary>`) rotate icon via `[details[open]>&>svg]`.
- `accordionContentClass` not need for native `<details>` — wrap content direct in `accordionContentInnerClass`.
- Single-open group — native `name` attribute on `<details>`, no script.
- **`detailsRevealClass`** = the `::details-content` height morph alone (`accordionItemClass` = glass chrome + it). Put on any `<details>` that is NOT an accordion row — a button-triggered disclosure keeps its own trigger recipe (`buttonVariants`) and still animates. **Content must be in the DOM before `open` flips** — a consumer that renders lazily on `toggle` animates `0 → 0` on first open; prerender on `pointerenter`/`pointerdown`/`focus` of the `<summary>` (landing `ProofPage/RatioHistory.astro`).
- **`detailsChevronClass`** — chevron for such a trigger; rotates via `[details[open]>summary_&]`, so it works under any summary recipe (`accordionTriggerClass` rotates its own direct `svg` child instead).

## Table density (Astro vs React)

`data-density="compact|default|comfortable"` on container with `data-slot="table-container"` overrides header height and cell padding. Default `default` (`h-10` / `p-2`); `compact` = `h-8` / `0.375rem 0.5rem`; `comfortable` = `h-12` / `0.75rem`. React wrapper (`<Table density="..." />`) forward attribute auto — in Astro attribute written by hand. CSS selectors duplicated: catch both per-cell `data-slot="table-head|table-cell"` (React) and bare `th`/`td` (Astro).

## Table vertical scroll (`tableViewportClass`)

Body that scrolls inside an existing surface (no second glass box): `tableViewportClass` on the wrapper — `overflow-auto overscroll-contain`, **height cap stays at the consumer** (landing `ProofPage/RatioHistory.astro`: `max-h-[9.5rem]` = head + 3 rows). Head scrolls with the body — **a sticky head needs an opaque fill, and every fill available reads as a white plank on the light theme** (`--muted` is `neutral-100`, glass tints resolve near-white); a transparent sticky head lets rows read through it. Consumer that rebuilds rows via `innerHTML` must save/restore `scrollTop`.

## Table expandable rows (`tableExpand*`)

Accordion-in-table recipe set (consumer: landing `ProofPage/Strategies.astro`). `tableExpandGroupClass` on `<tbody>` = named group `group/expand` + whole-group wash `data-[open]:bg-muted/20` (consumer script toggles bare `data-open`); `tableExpandTriggerClass` on trigger row (+ `tableRowClass`); `tableExpandAccentCellClass` on first cell — 3px `::before` accent bar via `start-0` (RTL-safe), shown on group hover AND open, color from **`--row-accent`** set inline per row by consumer (series color; gray mix for zero rows — no CSS fallback: Tailwind arbitrary values choke on nested `color-mix` commas); `tableExpandChevronClass` / `tableExpandDetailRowClass` / `tableExpandRevealClass` (grid-rows 0fr↔1fr morph) / `tableExpandPanelClass` (opacity fade, spacing stays at consumer). Detail panel is deliberately boxless — group wash IS the container, no `insetPanelClass` inside. Open state carries no `bg-primary` tint (removed from `tableRowClass`); `data-[state=selected]:bg-primary/15` stays selection-only. Non-expandable twin: `tableAccentRowClass` (on `<tr>`, group `/row`) + `tableAccentCellClass` — same `--row-accent` bar on plain row hover (consumer: landing `Composition.astro`, color = token brand sampled from the icon PNG, `TOKEN_ACCENT` in `ProofPage/data.ts`).
